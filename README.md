# Input datasets for the multi-scale hydrodynamic simulation of flood intrusion into a metro station

This archive contains the **complete input files** of the three SERGHEI-SWE simulations that constitute the
baseline scenario (**S0**) of the paper:

> **Multi-scale Hydrodynamic Simulation Framework for Flood Risk Assessment of Urban Metro Stations**
> Z. Li, H. Li, E. Martínez-Gomariz, B. Russo, D. Feng, D. Zhang
> *Journal of Flood Risk Management* (Special Issue: Physics-based Urban Flood Modelling)

The dataset reproduces the full modelling chain of the paper: rainfall-driven **overland flow** around the
station, flood **intrusion into the upper level (concourse)**, and the **cascading intrusion into the lower
level (platform)** through the internal staircases. It is provided so that every boundary condition and every
model parameter used in the study can be inspected and re-run by a third party.

---

## 1. What is (and is not) in this archive

**Included**

- All SERGHEI input files for the three coupled simulations (topography, roughness, rainfall, boundary
  conditions, observation points, solver parameters).
- The time series exchanged between the three models (entrance stage hydrographs, upper-level outlet
  hydrographs used as lower-level inlet boundary conditions).

**Not included**

- The SERGHEI source code. SERGHEI is an independent, open-source model and is distributed separately
  (see Section 2).
- Model output fields (NetCDF maps, gauge time series). These can be regenerated by running the inputs
  provided here.
- The raw source datasets used to build the overland model (FathomDEM tiles, the CMAB building dataset,
  OpenStreetMap extracts). Only the *derived* model grids are provided; provenance and licences are given
  in Section 8.

### Running a simulation

SERGHEI is executed as

```bash
./serghei <inputFolder/> <outputFolder/> <Nthreads>
```

for example

```bash
./serghei input-station-lowerlevel/ output-lowerlevel/ 1
```

The three input folders provided here are used verbatim as `<inputFolder/>`; no file names or paths inside
the folders need to be modified.

## 4. File-by-file description

| File | Meaning |
|---|---|
| `parameters.input` | Simulation control parameters (time, CFL, output, domain decomposition). |
| `sw.input` | Settings of the shallow-water module: initial condition, friction law, roughness, wet/dry threshold. |
| `dem.input` | Bed elevation, ESRI ASCII grid. |
| `gauges.input` | Observation points at which time series are written during the run. |
| `extbc.input` | External boundary conditions (inlets and outlets). Empty for the overland model. |
| `polygonN.input` | Polygons that define the cell set on which a boundary condition acts. |
| `hydrographN.input` | Time series prescribed at an inlet. |
| `roughness.input` | Manning *n* field, ESRI ASCII grid. |
| `rainfall.input` | Rainfall intensity time series (spatially uniform). |

## 5. Step-by-step reproduction

1. Build SERGHEI from https://gitlab.com/serghei-model/serghei at the version indicated in Section 2.
2. **Run the overland model**
   ```bash
   ./serghei input-overland/ output-overland/ 1
   ```
   Read the water-surface elevation time series at the four gauges (the station entrances), subtract the
   entrance sill elevation, and keep the part of the record after the exterior depth first exceeds 0.3 m.
   Convert to stage (*h+z*) and write `hydrograph1`–`hydrograph4` of the upper level (already provided here).
3. **Run the upper-level model**
   ```bash
   ./serghei input-station-upperlevel/ output-upperlevel/ 1
   ```
   Read the water depth at the eight staircase outlets (the brink cells carry Fr = 1) and convert to stage.
   These are `hydrograph1`–`hydrograph8` of the lower level (already provided here).
4. **Run the lower-level model**
   ```bash
   ./serghei input-station-lowerlevel/ output-lowerlevel/ 1
   ```

Because steps 2 and 3 depend on the output of the preceding step, the hydrograph files required to start
each model are already included. **The lower-level model can therefore be run directly, without running the two preceding models.**
